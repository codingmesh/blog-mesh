# Technical authors' personal blogs: primary-source notes

Research date: October 14, 2026 (America/Los_Angeles). Translated into US English on October 15, 2026; the observations below describe the original research session.

These notes verify author identities, links between personal sites and GitHub profiles, and content organization using first-party homepages, About pages, colophons, and GitHub profiles. The sample covers open-source development, frontend education, systems topics, and design engineering. **It is not a GitHub follower ranking**, and follower counts are not treated as a measure of technical ability. The patterns below are interpretations of content structure; visual details require separate screenshot verification.

## 1. Dan Abramov: writing first

- Blog: [overreacted.io](https://overreacted.io/). Personal links: [danabra.mov](https://danabra.mov/). GitHub: [gaearon](https://github.com/gaearon).
- Identity evidence: the personal links page includes GitHub, Overreacted, and React talks spanning several years. The GitHub profile links back and pins React-related projects. This supports selecting Dan as a React community author without relying on a current employer. [Personal links](https://danabra.mov/), [GitHub](https://github.com/gaearon)
- Observed structure: the homepage goes directly into a chronological article list with titles, publication dates, and short summaries. Topics extend beyond React to protocols, mathematics, and work updates. The entries themselves provide discovery and navigation. [Blog homepage](https://overreacted.io/)
- Design implication: inspect title, summary, and date hierarchy alongside long-form reading. This pattern suits writing with a recognizable voice. This is a research judgment.

## 2. Anthony Fu: personal hub and open-source archive

- Site: [antfu.me](https://antfu.me/). Blog: [posts](https://antfu.me/posts). GitHub: [antfu](https://github.com/antfu).
- Identity evidence: the site describes an open-source developer and design engineer, listing Vitest, Slidev, VueUse, and UnoCSS among created projects and Vue, Nuxt, and Vite among core-team affiliations. The GitHub profile connects the same site and projects. [Site](https://antfu.me/), [GitHub](https://github.com/antfu)
- Observed structure: Blog, Projects, Talks, and Sponsors sit alongside photography, equipment, and generative-art links. The post archive groups entries by year and includes dates, reading times, language indicators, an English Only option, and links to talks, podcasts, streams, and notes. [Homepage](https://antfu.me/), [Post index](https://antfu.me/posts)
- Design implication: work, public communication, and personal interests share one identity. The structure supports both a blog and an open-source portfolio. This is a research judgment.

## 3. Josh W. Comeau: interactive educational publishing

- Site and blog: [joshwcomeau.com](https://www.joshwcomeau.com/). GitHub: [joshwcomeau](https://github.com/joshwcomeau).
- Identity evidence: the About page lists senior engineering experience at Gatsby, DigitalOcean, and Khan Academy, teaching experience, and projects including use-sound and react-flip-move. Those projects also appear on GitHub. [About](https://www.joshwcomeau.com/about-josh/), [GitHub](https://github.com/joshwcomeau)
- Observed structure: Articles and Tutorials provides substantial introductions, with Browse By Category and Popular Content as additional discovery paths. Topics include CSS, React, Animation, JavaScript, and SVG; navigation also distinguishes courses and goodies. [Homepage](https://www.joshwcomeau.com/)
- The About page describes interactive pronunciation, unit switching, sound controls, and illustrations. These support the interpretation that interaction is part of the personal introduction; this source review did not operate those controls. [About](https://www.joshwcomeau.com/about-josh/)
- Design implication: the site is itself a teaching artifact, with explorable explanations forming part of the identity. This is a research judgment.

## 4. Julia Evans: a topic-organized knowledge archive

- Site and blog: [jvns.ca](https://jvns.ca/). GitHub: [jvns](https://github.com/jvns).
- Identity evidence: the About page identifies Julia as a software developer and introduces Wizard Zines. Site navigation links directly to GitHub. [About](https://jvns.ca/about/), [GitHub](https://github.com/jvns)
- Observed structure: the homepage starts with the latest ten posts, then groups older articles under topics such as Git, DNS, Terminals, Computer Networking, and How a Computer Thing Works. Popular posts, talks, projects, and an email digest provide other entry points. [Homepage](https://jvns.ca/)
- Editorial approach: the About page emphasizes making difficult systems concepts understandable and explorable, including through zines, with clarity, curiosity, and humility. [About](https://jvns.ca/about/)
- Design implication: once an archive grows, topic indexes keep older material discoverable. This is a research judgment.

## 5. Simon Willison: a technical log with multiple content types

- Site and blog: [simonwillison.net](https://simonwillison.net/). GitHub: [simonw](https://github.com/simonw).
- Identity evidence: the About page identifies Simon as the creator of Datasette and a co-creator of Django, documenting programming and development since 2002. [About](https://simonwillison.net/about/)
- Observed structure: search, tags, and a chronological stream coexist with Entries, Links, Quotes, Notes, Guides, and Elsewhere. Main navigation includes Newsletter, TILs, and Tools; entries retain timestamps and tags. [Homepage](https://simonwillison.net/)
- Subscriptions and archives: the About page describes combined, article-only, link-only, and per-tag Atom feeds. The source is public, and the site is described as a custom Django application. [About](https://simonwillison.net/about/), [Site source](https://github.com/simonw/simonwillisonblog)
- Design implication: frequent publishing can combine short notes, links, quotations, releases, and articles in one searchable archive. This is a research judgment.

## 6. Maggie Appleton: a digital garden and visual essays

- Site: [maggieappleton.com](https://maggieappleton.com/). GitHub: [MaggieAppleton](https://github.com/MaggieAppleton).
- Identity evidence: the site introduces a designer and developer with an anthropology background, writing visual essays about programming, design, and anthropology. The GitHub profile describes a design engineer, links to the site, and pins a digital-garden project. [Site](https://maggieappleton.com/), [GitHub](https://github.com/MaggieAppleton)
- Observed structure: The Garden organizes Essays, Notes, Patterns, Smidgeons, Talks, Podcasts, Library, Now, and About. The author describes a collection of ideas, notes, and essays growing over time. [Homepage](https://maggieappleton.com/)
- First-party design explanation: the colophon names Canela Display for headings, Canela Text for body text, and Lato for supporting text, with a fluid type scale. Content uses seedling, budding, and evergreen growth stages. The page also describes intended-audience information, unfinished-content notices, and book components. [Colophon](https://maggieappleton.com/colophon)
- Technical detail at the time of review: the colophon specified Astro and MDX. Gatsby and Next.js were historical versions, so older reviews should not be treated as current implementation evidence. [Colophon](https://maggieappleton.com/colophon)
- Design implication: knowledge maturity, connections between topics, and illustration can form a coherent identity without presenting every note as a finished article. This is a research judgment.

## 7. Sindre Sorhus: a product maker's hub with a blog

- Site: [sindresorhus.com](https://sindresorhus.com/). Blog: [blog](https://sindresorhus.com/blog). GitHub: [sindresorhus](https://github.com/sindresorhus).
- Identity evidence: the homepage describes a full-time open-source developer and app maker, with Apps and Code as primary destinations. Code links to the author's GitHub profile. [Site](https://sindresorhus.com/), [GitHub](https://github.com/sindresorhus)
- Observed structure: navigation includes Apps, Blog, Now, About, Contact, and Donate. Apps have categories for price and platform. Blog entries show a title, summary, month/year, and reading time, covering open-source collaboration, modules, and performance. [Homepage](https://sindresorhus.com/), [Blog](https://sindresorhus.com/blog)
- Design implication: a product developer's homepage may emphasize what they make, with articles explaining their thinking. It should not be compared directly to a writing-first homepage without accounting for that purpose. This is a research judgment.

## 8. Lee Robinson: biography, evergreen notes, and selected articles

- Site and blog: [leerob.com](https://leerob.com/). GitHub: [leerob](https://github.com/leerob).
- Identity evidence: the site describes an engineer and writer who previously worked on Next.js at Vercel. GitHub pins Next.js and next-mdx-blog and links to the site. [Homepage](https://leerob.com/), [GitHub](https://github.com/leerob)
- Observed structure: Bio has Default and Long options, followed by a Notes topic list and Blogs. Notes cover developer experience, documentation, personal software, and product engineering. Blog entries include month and year. [Homepage](https://leerob.com/)
- Freshness caveat: the current-employer descriptions on the site and GitHub did not agree during this review. These notes use the supported descriptions of engineer, writer, and former Next.js contributor without assuming which profile was updated later. [Homepage](https://leerob.com/), [GitHub](https://github.com/leerob)
- Design implication: separate evolving viewpoints from dated publications when output is selective and personal perspective matters. This is a research judgment.

## Framework for visual review

The structural patterns are writing first (Dan), personal work archive (Anthony), interactive tutorials (Josh), topic-based knowledge archive (Julia), frequent technical log (Simon), and digital garden (Maggie). Sindre and Lee add adjacent examples of a product hub and a curated personal index.

Visual comparison should use a consistent desktop width and inspect both the homepage and at least one article: title/body typography, column width, navigation density, list hierarchy, images, code blocks, and whether interaction helps understanding. These source notes did not measure performance, complete accessibility, or mobile behavior and cannot support scores for those dimensions.

# Style revision: a writing-first technical blog

Date: October 14, 2026. This round made substantial changes in response to feedback about the overall direction.

Translated into US English on October 15, 2026. This record describes the original revision; historical screenshot pixels have not been edited.

## Assessment and changes

The earlier large welcome message, book illustration, pale-green featured card, and serif headings created the feeling of a literary personal homepage. Although it passed some functional checks, it did not fully reflect Dan's writing-first approach or Anthony's compact archive structure from the initial research.

This revision made articles the primary content:

- The homepage used a name, a two-line introduction, and an article list. Three article titles were visible in a 1280×800 desktop viewport.
- The book illustration and separate featured card were removed. Featured status became a small metadata label.
- System sans-serif headings and body text replaced the previous display treatment, with neutral light/charcoal surfaces and limited green accents.
- Navigation, homepage, and article columns were realigned. Wide screens used side contents navigation; smaller screens used a collapsed version.
- Writing, Notes, and About adopted consistent typography, scale, colors, and copy direction.
- The additional Chinese font dependency was removed. The build directory was approximately 812KB at that point. This was disk size, not a measure of page transfer size or loading speed.

## macOS-style code blocks

The revision added decorative red/yellow/green dots, a centered language title, a right-aligned copy button, 10px corners, and a subtle shadow. The dots are explicitly aria-hidden and do not simulate nonexistent window controls. Shell snippets use a Terminal title; source snippets show their actual language.

Code remains 14px on desktop and 13px on phones, with high-contrast themes, horizontal scrolling, keyboard focus, copy feedback, and print rules. Copied content was checked against the source text.

## Validation

- Astro reported 0 errors, warnings, and hints; the production build succeeded.
- Five page types at 320, 375, 768, and 1280px produced 20 combinations without page-level horizontal overflow.
- Automated checks of light/dark homepages, light/dark code pages, and mobile code reported no confirmed violations. The native hidden dialog's aria-controls relationship still needed manual interpretation, as noted in the earlier review.
- Internal links, heading anchors, and a unique H1 passed across all ten pages.
- The work changed the presentation layer and did not add redundant styling tests.
- The site remained local. These checks did not constitute complete accessibility certification or public deployment validation.
